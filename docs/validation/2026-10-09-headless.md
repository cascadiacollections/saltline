## Native Android determinism

Built the simulation determinism binary through the pinned mise Rust
toolchain for Windows ARM64 and Android ARM64, using NDK 28.1.13356709 and
API 24. Ran the Android binary on the USB-connected Pixel 10 from
`/data/local/tmp`, then removed it. No app installation was required.

Both platforms produced digest `0x1b3cfe1e37a5c99b`: 200 runs, 9,090
logged decisions, 921 cleared screens, and zero replay divergences.
Reproduce with `mise exec -- cargo build --release -p salt-line-sim --bin
determinism`, the equivalent Android-target build, and
`tools/android_digest.sh BINARY --expect HOST_DIGEST` with the appropriate
Android linker and adb configured.

## Gameplay sweeps

Ran the release `batch` binary in 21 scenarios:

- Depth sweeps: 100 seeds and 120 screens, widths 320 and 400, builds base,
  drift, demo, precision, risk, and evolving; perfect skill and `--fast`.
- Economy sweeps: 200 seeds and 40 screens, builds base, evolving, and risk;
  each of perfect, steady, and rough skill, with `--aim scaled --fast`.

Together these validated 213,102 combat screens; supply screens are excluded
from that count. All passed the existing `MIN_SOLUTIONS` gate, with zero
unsolvable screens and zero Flat fallbacks. `--fast` stops candidate searches
at the gate cap; it does not measure the complete candidate distribution.

For the 40-screen scaled-aim economy runs:

| Build | Perfect exhausted | Steady exhausted | Rough exhausted |
| --- | ---: | ---: | ---: |
| base | 0/200 | 1/200 | 195/200 |
| evolving | 0/200 | 6/200 | 92/200 |
| risk | 0/200 | 3/200 | 160/200 |

These are solver-assisted modeled runs, not observed player outcomes. Rough
skill exhaustion is a balance investigation candidate; no tuning changed.
The separate existing 100-seed economy gates also passed unchanged: base
perfect (zero exhaustion, mean reserve 58..71), base steady (at most two
exhaustions, reserve 29..37), and evolving steady with scaled aim (at most
eight exhaustions, reserve 43..53).

Reproduce each scenario with `mise exec -- cargo run --release -p salt-line-sim
--bin batch -- --seeds N --screens N --width W --build BUILD --skill SKILL
--aim AIM --fast`, using the combinations above. Depth runs use flat aim.

## Coverage-guided fuzzing

Ran all eight existing cargo-fuzz targets under WSL Ubuntu 24.04 ARM64 with
nightly Rust and cargo-fuzz 0.13.2. Each target received a 60-second time
budget and a 15-second per-input timeout; libFuzzer reported 61 seconds per
completed target. Total: 26,652,136 inputs, no crashes or assertion failures.
Per-target counts are recorded in the JSON results.

Targets: save_parse, seed_parse, replay, match_log, layout_code, layouts_file,
history_file, and replay_code. From `fuzz/`, reproduce with
`mise exec -- rustup run nightly cargo fuzz run TARGET -- -max_total_time=60
-timeout=15`. Fuzzing is randomized; exact counts and coverage will vary.
Bounded fuzzing does not prove the absence of bugs.

Raw logs and a compressed generated corpus remain in the local ignored
`build/headless-fuzz/` and `build/headless-fuzz-corpus.tar.gz`; they are not
required to understand the committed results or rerun the commands.
